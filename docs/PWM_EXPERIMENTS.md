# Arduino ESP32-C3 协程软件 PWM 实验记录

## 目的与最终保留方案

测试 coro 驱动的软件 PWM，在 Arduino 框架下观察调度对 LED 呼吸效果的影响。
不使用 LEDC 等硬件 PWM。最终按用户选择恢复 `esp_timer` 驱动，保留 Arduino
正常中断、FreeRTOS 调度和看门狗；专用忙轮询、最高优先级和关闭中断均为实验，
不作为当前默认实现。恢复正常驱动不代表软件 PWM 的稳定性问题已经解决。

当前 `esp32-c3-arduino` 与 `esp32-c3-baremetal` 共用 PWM、呼吸灯、协程调度器
和配置；C3 的 GPIO、系统计时器与周期计数器访问代码也共用。

| 参数 | 两个 C3 环境的公共设置 |
| --- | --- |
| 引脚 | GPIO 3、4、5 |
| PWM 频率 | 每路 1000 Hz |
| 占空比范围 | 0～30%，百万分比接口 |
| 呼吸周期 | 2、3、4.5 秒 |
| 亮度计算 | Q16 三角渐变后平方校正 |
| 更新间隔 | 1 ms，绝对截止时间 |
| PWM 载波相位 | 0、333、666 μs |
| 短脉冲处理 | 周期计数器等待；较长脉冲提前 16 μs 唤醒后等待下降沿 |
| CPU | 40 MHz |

比较前先统一这些算法和参数，避免把不同的亮度步进或脉冲实现归因于框架。
S3、原版 ESP32 和 ESP8266 的平台能力不同，不属于本次 C3 的硬件对照结论。

## 尝试与观察

| 方案 | 执行方式 | 实际观察及限制 |
| --- | --- | --- |
| Arduino 主循环轮询（早期） | `loop()` 驱动协程 | 用户观察到约每 2 秒卡顿；所用 Arduino 单核主循环源码有每约 2 秒执行 `vTaskDelay(5)` 的路径。它可解释主循环软件 PWM 的周期性停顿。 |
| `esp_timer` 驱动 | `ESP_TIMER_TASK` 一次性定时器；25 μs 内忙等待，100 μs 回调预算；主循环不驱动 PWM | 避开主循环暂停后仍不够稳定；统一 bare 算法后，用户仍确认 Arduino 效果有问题。 |
| 专用高优先级任务 | 固定在启动核，优先级 23，持续 `executor.poll()`，不主动延时 | 用户反馈“好一些了，但是还是会有问题”。需要取消所在核空闲任务的任务看门狗订阅，改为监控轮询任务，每 100 ms 喂狗；低优先级任务可能无法运行。 |
| 专用最高优先级任务 | 优先级 `configMAX_PRIORITIES - 1`，此配置为 24；仍开启中断 | 烧录后观察 8 秒无重启或看门狗报告，启动日志确认最高任务优先级模式。用户反馈“还不行”。最高任务优先级不会屏蔽硬件中断。 |
| C3 关闭中断对照 | 专用任务启动后保持临界区，清除 RISC-V 全局中断使能，清零 CPU 中断输入掩码，关闭相关看门狗，再持续轮询 | 用户实测反馈“好的多了，但是很偶尔也会有问题”。此模式已停止正常 RTOS 调度和后台服务，不能代表正常 Arduino 运行条件。 |

## 关闭中断实验遇到的问题

初版启动日志读回 `MIE=0`、CPU 中断掩码 `00000000`，确认关闭动作已生效，
但随后出现 abort。地址解析指向 Arduino libc 的 `lock_acquire_generic` 和递归锁路径：
调度器清理启动回调涉及释放堆内存，不能直接假定所有操作都可在关中断后执行。

随后增加了“先开中断排空启动回调、释放其节点，再关闭中断”的处理。
稳态侵入式定时等待本身不分配队列节点。该修订构建通过，但重刷期间出现串口
包头错误和传输中断，助手未完成其独立的启动验证。用户的改善反馈记录为实测
观察，不据此声称所有修订镜像均已验证。该实验代码及编译开关最终已移除。

## 可以得出的结论

- 主循环中的周期性让出 CPU 会直接影响由主循环驱动的软件 PWM。
- 专用忙轮询较定时器回调驱动有所改善，但提升到最高任务优先级仍未解决问题。
- 用户观察到关闭中断后进一步改善，支持中断或抢占是影响因素之一；尚不能定量
  区分任务唤醒、RTOS tick、其他中断和具体代码路径各自造成的延误。
- 不能根据这些观察认定 coro 本身存在缺陷，也不能认定 Arduino 完全无法产生
  可用的软件 PWM。结论只适用于这块 C3、当前固件设置和 LED 实测条件。
- 关闭中断后仍有偶发问题，其原因尚未定位。缓存/取指、GPIO 实际脉宽、最低
  可输出脉宽和视觉响应等只能作为后续检查方向，当前没有测量证据支持归因。

以上主要是用户肉眼反馈、启动日志和构建验证，尚无逻辑分析仪或示波器的波形
记录。无重启只证明观察窗口内没有对应日志，不证明脉冲无抖动。若继续定位，
应同时测量实际 GPIO 周期/高电平宽度，并在不逐周期打印串口的条件下统计
唤醒迟到量，区分调度延迟与 LED 暗部亮度变化。

## 当前对比方式

```sh
pio run -e esp32-c3-arduino -t upload
pio run -e esp32-c3-baremetal -t upload
```

两者使用相同接线。Arduino 当前恢复正常 `esp_timer` 驱动；bare target 仍使用
裸机轮询。源码恢复不自动改变板上固件，应以最近成功烧录的镜像为准。
